# 開発での Claude の使い方（記録）

2026-11-04 時点。Claude Code の会話記録から、道具の呼び出しを機械で数えた値です（返事の記録だけを数え、同じ呼び出しの重複は除く。2026-11-04 夕方の時点で、開発と監査は今も増えています）（会話記録そのものは作者の端末にあり、公開していません）。

## 別の AI と上位モデル

- 別の AI（Codex）: 独立したコードレビューと、議論の審判に約15回。
- advisor（Claude の上位モデル）: 方針を決める前と、完了と言う前の相談に21回。

## Skills・MCP・hook（作者の個人の設定。リポジトリの外）

- Skills: 要件のすり合わせ（grill-me）、レビュー先の選び方（review-routing）、コードレビュー（code-review）。監査のセッションで動画（hyperframes）とコピー（copywriting）。
- MCP: ブラウザ（claude-in-chrome）で、普段の Chrome の画面を読む・操作する。メールの読み取り。
- hook: 開発中に実際に働いた物は、返事を日本語にさせる門、「公開した」などの状態を言う前に一次の証拠を見させる門、破壊的な操作を止める門、大きな画像を縮小させる門。

## 自前の検査道具（このリポジトリ）

- `tools/route_suite.mjs`: 経路 420組×昼夜＝840件。前回との差分で、遠回り・経路なしの増減を見る。
- `tools/persona_test.py`: 模擬の利用者100通り（端末・回線・使い方の違う台本。実在の利用者ではない）をブラウザで動かし、詰まった所・画面の禁句・エラーを集める。
- `tools/check.py`、`worker/test/`: 画面の基本の動き、中継の入力検査・上限、画面の Claude の出力の照合。

## 画面の中の Claude（経路の相談）

- モデル: Opus 5.5。道具は3つ（`find_routes`・`assess_route`・`places_along`、`src/agent-tools.ts`）、最大7往復。
- 出力の照合（`src/agent.ts` の `validateOutput`）: 禁止語・道具の結果に無い数字・実在しない根拠を落とし、決まった文に差し替える。
- 本物の答えの採点（`tools/agent_eval.mjs`）: 事情30通りを本番の中継に送り、機械の決まりで採点。1回目 24/30（[docs/agent_eval_round1.md](agent_eval_round1.md)）、失敗の原因2つを直して、失敗・差し替えのあった8通りを測り直し 8/8（[docs/agent_eval_round2.md](agent_eval_round2.md)）。その後 30通りを通しで測り直し **30/30**（[docs/agent_eval_round3.md](agent_eval_round3.md)・照合で「記録の限界」の文を落としたのが3通り（「安心」「保証」を含んでいたため））。2周目のレビューの直しの後、32通りで 31/32（[docs/agent_eval_round4.md](agent_eval_round4.md)）。落ちた1通りは緊急の言い方の取りこぼしで、言い方を足して測り直し合格。1回目の後に、引き換えの判定を「要約の最初の文」から「要約のどこかで件数を挙げる」に緩めた（緊急の時は110番を先に言わせるため）。
- 中継（`worker/`）: 鍵はブラウザに置かない。指示（system）と道具は中継側で固定。回数に上限。

## 使っていない物

Managed Agents、Agent SDK、Workflow（多数のエージェントを台本で動かす機能）、playwright の MCP（画面の検査は Python の Playwright のスクリプトで行った）、Claude Desktop、Cowork。
